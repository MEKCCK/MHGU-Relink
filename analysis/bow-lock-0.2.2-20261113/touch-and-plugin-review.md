# 弓锁定、触控与自动准线插件核对

日期：2026-11-13。此记录仅归档已核实的现象与源码路径，不修改生产源码，不改变用户已接受的“目标区长按半秒切换锁定开关”手势。

## 已证实：本次锁定关闭来自目标区长按路径

日志中所有可见的锁定关闭均为 `[touch] lock-on off (target held)`，位于第 670、719、758、761、766、772、793 行。日志没有出现 `[touch] lock-on off (no hunt camera)`。

例如第 663 行先出现 `lock-on on`，第 670 行为 `lock-on off (target held)`，第 671 行为 `lock-on on (target held)`。这些日志由宿主 `runtime/touch.cpp:1111–1126` 的 `F_TARGET` 释放路径输出，可以确认是目标触控手势改变了宿主锁定状态，不能归因于本次日志未出现的猎场摄像机超时路径。

当前目标区手势如下：

- 按下后没有超过移动阈值，且在 300 ms 内正常抬起：短按。
- 按下后没有超过移动阈值、没有取消，且至少 500 ms 后抬起：长按，执行一次 `s.lock = !s.lock`。
- 300–500 ms 之间的静止抬起：既不算短按也不算长按，不执行目标动作。
- 移动阈值为屏幕高度的 2.5%；取消事件不改变锁定。
- 已锁定时短按目标区调用 `mousecam_target_cycle()`；未锁定时短按启用锁定。

长按开关在手指释放时执行一次，不是按住期间逐帧切换。本次只记录现有行为，保留该语义。

## 已证实：已捕获的射击／瞄准触点不会拖动变成目标触点

`runtime/touch.cpp:992–1019` 的按下处理首先调用 `hit(...)` 检测实际控制按钮，`c >= 0` 时捕获为 `F_BUTTON`。只有按钮未命中、未命中前面的物品／箭头区域、且不在菜单内时，目标矩形才会捕获为 `F_TARGET`。

`runtime/touch.cpp:1053–1071` 的移动处理允许 `C_RFIRE`／`C_RAIM` 触点继续产生镜头拖动；它们保持原来的 `F_BUTTON` 身份。把已按住的射击／瞄准手指滑入目标矩形，不会把这个手指改成 `F_TARGET`，也不会因此触发目标长按开关。

因此，现有代码不支持“射击／瞄准触点在拖动时变成目标长按”的解释。仍有一种未证实可能：触点最初按下的位置就没有命中实际按钮，而命中了目标矩形，例如自定义布局或 HUD 区域与画面预期不一致。本次日志没有 `MHGU_TOUCH_LOG` 触点坐标，也没有对应的已保存布局，不能确认或排除这种按下时的命中偏差。

目标触控矩形由 `zone_rect(..., TZ_TARGET, ...)` 从 HUD 部件范围与边距生成，并经过画面映射／宽屏压缩；真实按钮命中优先于该矩形。本次没有建立具体的 21:9／32:9 目标几何错误证据。

## 已证实：插件加载并挂接弓输入映射；不能据此认定它关闭宿主锁定

日志第 87–89 行确认加载 `bow_auto_aim.nro`，模组目录名为 `MHGU弓蓄力自动准线接刚射会关不掉`。第 450 行输出挂接点 `0x013b1dc8`、签名 `e92d48f0`、槽地址 `0x0194ec0c`，并显示 `valid=true`；第 452 行输出 `Bow Type 1 auto aim hook installed`。

`runtime/hle/input_view.c:67–69` 的武器映射表中，`mappers[9]` 是 `0x13b1dc8`，对应武器编号 10（弓；游戏武器编号跳过 5）。这证明插件参与了与宿主弓输入映射有关的同一客体代码挂接链。这里是数组下标 **9**，不是 10。

宿主锁定标志 `s.lock` 位于 `touch.cpp` 内部的宿主 `State`。日志中的 `(target held)` 由上述宿主手势路径产生，不能从插件挂接日志推断为插件直接修改了该宿主标志。现有证据没有建立插件与这些锁定关闭之间的因果关系。

宿主 `runtime/hle/mousecam.c` 的锁定射击辅助写入猎人朝向与俯仰字段（`PL_AIM_YAW`、`PL_AIM_PITCH`、`PL_AIM_PITCH2`、`PL_AIM_LEAN`）。`lock_aim()` 还同时要求 `config_live_persistent_lock_on()` 和 `touch_lock_on()` 成立。`PersistentLockOn` 的默认值为关闭，但本次日志不包含用户实际保存的设置，不能把默认值当作实机当前值。

## 待核实：画面疑似 Type 2，插件自报 Type 1

父任务的画面检查发现射击／蓄力按钮标记为 **R**，瞄准标记为 **X**。根据当前 `runtime/touch.cpp:274–280` 的 `ranged_buttons()`，在弓已拔出的条件下，这组标记对应游戏的 **Bow Controls Type 2**。插件日志则自报 **“Bow Type 1 auto aim hook installed”**。

这是需要核对游戏弓操作设置与插件适用条件的线索，**不是已经确认的兼容冲突或故障原因**。本次未获得并检查实际插件二进制／源码，日志标签也可能只是固定字符串；不能据该标签断言插件仅支持 Type 1，或断言它导致蓄力准线无法关闭。
